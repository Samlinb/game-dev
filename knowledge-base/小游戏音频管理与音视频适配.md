# 小游戏音频管理与音视频适配

适用：团结引擎 / Unity 2022.3 WebGL 构建，微信 + 抖音小游戏，2D 休闲。
触发：实现 BGM/音效播放与开关、选音频方案/格式、排查小游戏音频不响/卡顿/循环异常、接视频播放。
核对日期：2026-11-13（微信官方适配文档 Design/AudioAndVideo.md 经镜像取得 + 模板 AudioManager 项目实测）。原页待浏览器复核。
前置：音频偏好与存档分离的架构决策见 [Unity 小游戏项目架构](<./Unity 小游戏项目架构.md>)；BGM 不进首包见 [小游戏启动优化](./小游戏启动优化.md)。

## 结论（影响行动的部分）

1. **首选 UnityAudio（Unity 原生 AudioSource），已自动适配微信小游戏**；长音频走 InnerAudioContext、短音频走 WebAudioContext，插件按文件大小自动切换。FMOD 全走 WebAudio，**不要用它放大 BGM**（占内存）。
2. **音频格式推荐 mp3 或 aac**（双端兼容好）；本项目用 AAC 低码率（架构条目约定）。
3. **BGM 走远程加载，不打进首包**（模板 AudioManager 注释明确；启动优化要求）。
4. **音乐/音效开关用独立 PlayerPrefs 键（audio_*），不混进游戏存档**（模板实现）。
5. **限制同时播放的音频数量**——同播过多会卡顿（官方 QA）。
6. **iOS 17.5+ 退后台返回音效可能不续播**（已知问题，更新插件缓解）；iOS 偶现 `operateAudio:fail jsapi has no permission` 可忽略。

## 一、音频方案选型（官方文档，镜像取得）

来源：微信官方适配文档 `Design/AudioAndVideo.md`，经镜像 BlackTom900131/minigame-unity-webgl-transform 取得（gh api，2026-11-13）；原页待浏览器复核。官方文档内容。

| 方案 | 适配机制 | 适用 | 注意 |
|------|----------|------|------|
| **UnityAudio（推荐）** | 已自动适配微信小游戏；长音频→[InnerAudioContext](https://developers.weixin.qq.com/minigame/dev/api/media/audio/InnerAudioContext.html)，短音频→[WebAudioContext](https://developers.weixin.qq.com/minigame/dev/api/media/audio/WebAudioContext.html)，按文件大小自动切换 | BGM + 音效 | 优先使用 |
| FMOD | 全部走 WebAudio | 复杂音频中间件需求 | **不推荐 BGM 等大文件**（WebAudio 占内存大）；旧引擎 FMOD error 36 需升级 |

**判断条件**：普通 BGM+音效用 UnityAudio 即可；只有需要 FMOD 高级音频设计时才用 FMOD，且大文件避开。

## 二、模板 AudioManager 实现对照（项目实测）

路径：`projects/MiniGameTemplate/Assets/_Project/Scripts/Core/AudioManager.cs` + `Data/AudioConfig.cs`（2026-11-13 Read 核实）。

**架构**：
- 单例 `AudioManager.Instance`，`DontDestroyOnLoad`，Awake 建 sfx 查表。
- **双 AudioSource**：`musicSource`（BGM 常驻循环 `loop=true`）+ `sfxSource`（音效 `PlayOneShot`），由一键初始化在 Boot 场景建好并引用。
- **开关持久化**：`audio_music_on` / `audio_sfx_on` 两个 PlayerPrefs 键，`SetMusicOn/SetSfxOn` 写入并 `PlayerPrefs.Save()`；**与游戏存档分离**（存档走 SaveManager，见架构条目）。
- **音效查表**：`AudioConfig.sfx`（key→AudioClip 列表）→ `Dictionary` 查表，`PlaySfx(key)` 播放。
- **AudioConfig**（ScriptableObject）：`bgm` AudioClip、`musicVolume`(0.7)/`sfxVolume`(1.0)、`sfx` 表。

**最小调用**：
```csharp
AudioManager.Instance.PlayMusic();        // 播 BGM（受 IsMusicOn 控制）
AudioManager.Instance.PlaySfx("click");   // 按 key 播音效（受 IsSfxOn 控制）
AudioManager.Instance.SetMusicOn(false);  // 关音乐（持久化）
```

**出包要点**（模板注释）：BGM 走远程加载（ResManager 拉取），别打进首包。

| 项 | 建议 | 来源 |

## 四、WebGL / 小游戏音频坑（官方 QA，镜像取得）

来源：镜像 AudioAndVideo.md QA 段（2026-11-13）。官方文档内容。

| 现象 | 原因/处理 |
|------|-----------|
| **iOS 17.5+ 退后台返回音效不续播** | 已知问题，更新最新导出插件缓解，官方持续兼容 iOS 更新 |
| iOS 偶现 `operateAudio:fail jsapi has no permission` | 播放时退后台可能出现，**无实际影响可忽略** |
| 音频播放时游戏卡顿 | 同时播放音频数量过多→**限制同播数量** |
| 部分音频安卓无法循环 | 已知问题，**8.0.51 客户端修复** |
| PC 端无法循环播放完整音频 | 已知问题，更新最新 Unity 导出插件 |
| FMOD error code 36 | 旧引擎已知问题，升级 Unity 引擎版本 |

**排查顺序**：先确认格式（mp3/aac）→ 再看同播数量 → 再看客户端/插件版本（循环类问题多为版本已知 bug）→ iOS 权限报错可忽略。

## 五、视频播放（官方文档，镜像取得）

来源：镜像 AudioAndVideo.md 视频段（2026-11-13）。

- **VideoPlayer 组件已自动适配**微信小游戏；纯全屏视频也可用 [WXVideo API](https://developers.weixin.qq.com/minigame/dev/api/media/video/wx.createVideo.html)（全屏场景更推荐小游戏原生视频能力）。
- **VideoPlayer 最低支持版本**：iOS 高性能+ 8.0.55 / iOS 高性能 8.0.41 / 安卓 8.0.40 / PC 基础库 3.2.1 / 开发者工具 基础库 3.2.1+1.06.2310312。
- 路径支持 CDN、微信本地文件路径、streamingAssets（最新插件支持本地缓存减少重复下载）。
- iOS 坑：高性能模式只能同时播一个视频（iOS 播放策略）；`videoPlayer.frame` iOS 不支持；iOS 有声无画查高性能+插件版本或 frame 设置；跨域报错 `Origin weapp://wechat-game-runtime is not allowed by Access-Control-Allow-Origin` 需服务端配微信跨域。
