# 小游戏启动优化（首屏 TTI）

适用：团结引擎 / Unity 2022.3 WebGL 构建，微信 + 抖音小游戏平台。
触发：首屏加载慢、启动留存低、抖音评测启动分不达标。
核对日期：2026-11-12（团结 docs.unity.cn + 抖音评测标准）；2026-11-13 round 24 经镜像核实微信官方启动指南、round 27 核实预下载（UsingPreload，见 §五）、round 43 核实 Shader 异步 Warmup（团结官方页 + 镜像，见 §4.1）、round 44 核实微信系统字体 WX.GetWXFont（镜像，见 §2.1）、round 51 核实启动封面定制（镜像，见 §4.2）、round 52 核实 Loader CDN/首包加载/调试日志（镜像，见 §4.3）。微信启动场景分析工具用法仍待核对（见末尾）。

## 结论（影响行动的部分）

1. **启动耗时 = 下载首包 + 下载/编译 WASM + 引擎初始化/首场景加载**。三段串行，单线程模型，任何一段膨胀都直接加到 TTI 上。
2. **首包精简是 ROI 最高的手段**：Build Settings 仅留首场景、去 Resources、Shader 变体裁剪、字体走宿主。团结引擎默认资源已优化到 341KB，用户侧空间主要在场景和代码。
3. **WASM 体积决定下载+编译两段**：Managed Stripping High + Strip Engine Code + 代码分包，典型 30MB wasm → Brotli 6MB → 分包后首包更小。
4. **抖音有量化评测标准**（FP80/TTI80 分档），微信有启动场景分析工具（待核对具体用法）。优化目标应对照平台阈值而非凭感觉。
5. **模板 Boot 场景已遵循最小化原则**：BootLoader 只做一行 LoadScene 调用，LoadingManager 代码构建 UI 不依赖 Prefab/资源加载。

## 一、启动链路三阶段（官方规定）

来源：[团结小游戏启动分析](https://docs.unity.cn/cn/tuanjiemanual/Manual/minigame-loading-analysis.html)，核对 2026-11-12。

| 阶段 | 内容 | 主要影响因素 |
|------|------|-------------|
| 1. 下载首包数据文件 | data package（场景、Resources、全局设置、il2cpp metadata、引擎默认资源） | 文件体积、CDN 压缩（gzip/br） |
| 2. 下载和编译 WASM | wasm 代码文件下载 + 浏览器编译 | wasm 体积、设备 CPU |
| 3. 引擎初始化 + 首场景加载 | il2cpp 初始化、Shader 解析、MonoBehaviour Awake/Start、纹理 GPU 上传 | 代码量、Shader 变体数、首场景复杂度 |

关键机制：
- **单线程**：无独立渲染线程，纹理/模型 GPU 上传和 Shader 编译均阻塞主线程。
- **Shader 解析耗时**：keyword 解析 + 变体数据解压与加载，变体越多越慢。
- **C# 执行占比大**：类构造函数、Awake/Start 调用都在此阶段。

**Unity Loader 工作流（镜像 Startup.md 核实，round 33）**：启动准备阶段**资源(data)与代码分包(wasm.code.br)两分支并行**——资源处理 = 下载/解压/保持内存（构建场景及依赖 + Resources 目录 + 引擎默认内建资源），代码分包处理 = 下载/解压到内存/编译/实例化；完成后进入引擎初始化 + 首场景加载。**二次启动默认用本地缓存**（首包资源/资源分包再次启动直接读缓存，加速二次启动；真机下拉历史栏删除小游戏可清缓存）。CDN 需放：首资源包 `webgl/ProjectName.data.unityweb.bin.txt` + Addressable/AssetBundle 资源分包。

## 二、首包精简操作清单（官方规定）

来源：[团结首包数据文件精简](https://docs.unity.cn/cn/tuanjiemanual/Manual/minigame-loading-resources-opt.html)，核对 2026-11-12。

### 必做（高 ROI）

| 操作 | 路径/方法 | 效果 |
|------|-----------|------|
| Build Settings 仅保留首场景 | 其余场景走 AB/Addressables/Streaming 加载 | 首包不含后续场景数据 |
| 避免 Resources 文件夹 | 改用 AB 或 AutoStreaming | Resources 全量进首包 |
| 取消 Auto Graphics API | Player Settings → 仅勾 WebGL 2.0（或 1.0） | 减少 Shader 变体 |
| 清理 Always Included Shaders | Project Settings → Graphics → 移除未使用 | 减少 Shader 编译耗时 |
| Quality 只保留一个等级 | Project Settings → Quality → 取消未用 | 减少变体 |
| 字体走宿主平台 | 团结支持运行时加载宿主中文字体（微信 WX.GetWXFont 详见 §2.1） | 避免 2–3MB 字体进首包 |

### 进阶

- **资产流式加载**：AutoStreaming / TextureManager（团结内置），或 AB/Addressables 自管。
- **首场景文字少时用纹理展示**，或为首场景文字生成 TMP 静态字体贴图。
- **Il2cpp metadata 与代码量正相关**：精简 WASM 同时减小 metadata。

### 查看工具

| 工具 | 用途 | 位置 |
|------|------|------|
| Asset Browser | 查看二进制数据包中资源信息 | 团结 ≥1.8.0 内置 |
| ExtractDataUnityWeb | 首包解开成多文件 | Editor/Data/Tools |
| WebExtract | 从 AB 解压序列化文件 | Editor/Data/Tools |
| Binary2Text | 二进制→文本（需 TypeTree） | Editor/Data/Tools |

### 2.1 微信系统字体（WX.GetWXFont，省首包字体下载）

来源：微信适配文档 Design/WXFont.md（官方文档内容·镜像取得 BlackTom900131/minigame-unity-webgl-transform，gh api 核实 2026-11-13；原页待浏览器复核）。

中文字体 2–3MB，用微信系统字体从本地加载可省启动下载；不支持时回退 CDN 后备字体。**必须提供 CDN 后备字体**——iOS18 暂不支持微信系统字体，无后备字体无法正常使用。

**版本要求**（硬约束）：

| 项 | 要求 |
|----|------|
| 转换插件 | ≥ 202306292010（提供 `WX.GetWXFont` 接口） |
| 安卓微信客户端 | ≥ 8.0.34（可本地加载，无需下载） |
| iOS 微信客户端 | ≥ 8.0.39（可本地加载） |
| iOS 18 | **暂不支持系统字体，必须后备字体** |

不满足客户端版本：首次网络下载，符合缓存规则后续走本地文件缓存（FileCache），故 CDN 后备字体不可省。

**接入示例**（官方文档示例代码）：

```csharp
var fallbackFont = "https://your-cdn.com/字体文件.ttf";
WeChatWASM.WX.GetWXFont(fallbackFont, (font) =>
{
    text.font = font;                                    // uGUI Text
    tmpText.font = TMP_FontAsset.CreateFontAsset(font);  // TMP
});
```

**字符集裁剪**：GetWXFont 加载的字体集合可在转换面板自定义 Unicode 范围，减少字体文件大小（基本汉字 0x4E00–0x9FFF + 拉丁 0x0–0x7F + 中文标点 0x3000–0x303F 等，特殊字符按需填入）。

**调试日志**（开插件调试日志，过滤 `[font]`）：
- `load font from local` = 用了系统字体；`load font from network` = 走了 CDN 后备。
- 异常 `无中文字体`：本地无可用系统字体（常见安卓系统 <7.1）；`无字体文件内容`：读取失败，提供微信日志给平台排查。

## 三、WASM 代码精简（官方规定）

来源：[团结 Wasm 代码精简](https://docs.unity.cn/cn/tuanjiemanual/Manual/WasmCodeReducing.html)，核对 2026-11-12。

### 配置清单

| 配置 | 路径 | 推荐值 |
|------|------|--------|
| Managed Stripping Level | Edit → Project Settings → Player → Other Settings | **High** |
| Strip Engine Code | 同上 | 开启 |

### 代码分包

**抖音 Wasm 分包工具**（来源：[Wasm分包工具说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/rd-to-SCgame/open-capacity/performance-optimization/start-up/code-upload/sc_webgl_split)，更新 2026-08-26，核对 2026-11-11）：
- 典型 wasm 约 30MB，Brotli 压缩后约 6MB。
- 工具把 wasm 拆成启动首包 + 延迟分包。
- 入口：抖音开发者工具 ≥ 4.3.2 顶部工具栏。
- 需真机预览收集函数（覆盖启动后最先进入的场景/关卡），发布后自动开启线上函数收集。

- 检查 `Library\Bee\artifacts\WeixinMiniGame\ManagedStripped` 目录确认裁剪结果。
- 用 dotPeek 分析 dll 确认必要代码未被误裁。

## 四、引擎初始化加速（团结内置，v1.2.0+）

来源：[团结引擎启动优化](https://docs.unity.cn/cn/tuanjiemanual/Manual/minigame-loading-engine-opt.html)，核对 2026-11-12。

| 优化 | 机制 | 效果 |
|------|------|------|
| 默认资源精简 | ASTC 替代 RGBA + 移除 ComputeShader | 593KB → 341KB |
| Slim Format metadata | 按实际方法数选紧凑结构 | 案例 15.3MB → 13.3MB（~15%） |
| il2cpp 泛型初始化 | 数组替代 HashMap | 省 ~20% 初始化时间 |
| Shader 变体延迟加载 | 启动只加载表头，使用时按需加载 | 减少首帧阻塞 |
| MonoScript 懒加载 | 不再启动时反序列化全部 MonoScript | 减少 MonoManager 初始化 |
| GLES 初始化 | WebGL2.0 跳过逐格式 MSAA 查询 | 加速图形设备初始化 |

配置：`Edit → Project Settings → Use Slim Format For global-metadata.dat`（默认开启）。

### 4.1 Shader 异步 Warmup（SVC 预热，团结引擎 + 微信）

来源：[团结引擎 Shader 异步 Warmup](https://docs.unity.cn/cn/tuanjiemanual/Manual/WeixinAsyncShaderWarmup.html)（WebFetch 核实 2026-11-13，官方规定）+ 微信适配文档 Design/AsyncShaderWarmup.md（镜像取得，平台开通条件原页待浏览器复核）。

**与上表「Shader 变体延迟加载」互补**：延迟加载是启动只加载表头、用时按需；Warmup 是主动预编译变体避免运行时首次编译卡顿。变体多时同步 `WarmUp()` 本身会长卡顿 → 用异步。

**原理**（团结官方）：WebGL 无 binary shader，每个 shader 编译/link/状态检查几十~几百 ms；在支持 `KHR_parallel_shader_compile` 扩展的浏览器上，用 `GL_COMPLETION_STATUS_KHR` 代替 `GL_LINK_STATUS` 做非阻塞状态查询，把 Warmup 异步化。

**API 与时序**（团结官方，示例代码）：

```csharp
var svc = Resources.Load<ShaderVariantCollection>("ShaderVariants");
AsyncOperation op = svc.WarmUpAsync();   // 替代阻塞的 WarmUp()
op.completed += _ => { /* 完成后再进游戏场景渲染 */ };
// 轮询 op.progress 显示进度
```

- 在耗时操作（网络请求/数据 IO）**前**启动 Warmup，`completed` 触发后再渲染；过早渲染会回退同步编译卡顿。
- 实测（iPad mini 6 / A15 / iOS 17.5.1 / 79 变体 / NoDevelopment 模式）：异步总耗时 ≈3599ms、主线程阻塞 ≈125ms；同步总耗时 ≈4173ms 全阻塞。**主线程阻塞从 ~4173ms 降到 ~125ms**。

**微信平台开通条件**（镜像 AsyncShaderWarmup.md，原页待复核）：

| 项 | 要求 |
|----|------|
| 微信客户端 | ≥ 8.0.54 |
| 基础库 | ≥ 3.7.4（小游戏调试面板第一条日志查看） |
| 功能申请 | 需[申请开通 Shader 异步 Warmup](https://doc.weixin.qq.com/forms/AJEAIQdfAAoACQA2gY2AD41GisQUxXTEf)（镜像登记链接）等待通过 |
| game.json | `"enableParallelShaderCompile": true` |

**平台支持矩阵**（镜像）：iOS 普通模式**不支持**；PC + iOS 高性能模式支持（系统自带，无需配置）；Android + iOS 高性能+ 模式用平台能力，需开发者配置。

### 4.2 启动封面定制（loadingPageConfig，平台原生 Loading 页）

来源：微信适配文档 Design/CustomLoading.md（官方文档内容·镜像取得 BlackTom900131/minigame-unity-webgl-transform，gh api 核实 2026-11-14；原页待浏览器复核）。

Unity WebGL 启动需时间，平台原生 Loading 页（引擎启动前）用图片/视频+进度过渡留住玩家。**与 §六 LoadingManager 互补**：封面覆盖引擎启动阶段，LoadingManager 覆盖进引擎后的场景加载。可自定义：加载图/视频、文案及样式、进度条样式、封面隐藏时机。

**转换插件配置**（导出面板）：

| 配置 | 作用 | 模板变量 |
|------|------|----------|
| bgImageSrc | 启动封面图 | $BACKGROUND_IMAGE |
| VideoUrl | 启动视频 | $LOADING_VIDEO_URL |
| HideAfterCallMain | callmain 完成后立即隐藏封面 | $HIDE_AFTER_CALLMAIN |
| loadingBarWidth | 进度条宽度 | $LOADING_BAR_WIDTH |

**game.js 样式配置**（无转换插件入口，改 `wechat-default/game.js` 的 `loadingPageConfig`）：
- `totalLaunchTime`：默认总启动耗时（加载动画播放时间，默认 15000ms，按实际调整）。
- `designWidth/designHeight`：设计宽高（默认 667×375，**改后需同步改文字/进度条样式**）；`scaleMode`：缩放模式（常用 `NO_BORDER` 不留黑边 / `FIXED_HEIGHT` 高度适配 / `FIXED_WIDTH` 宽度适配，另有 EXACT_FIT/SHOW_ALL/FIXED_NARROW/FIXED_WIDE）。
- `textConfig`：分阶段文案 firstStartText（首次）/downloadingText[]（加载循环）/compilingText（编译）/initText（初始化）/completeText（完成）+ textDuration（多文案每条展示时间）+ style。
- `barConfig`：进度条样式；`materialConfig`：backgroundImage/backgroundVideo/iconImage（图+视频都填时先图后视频）。

**封面硬约束与技巧**（UsingLoader.md，镜像核实 2026-11-14）：
- `backgroundImage` 宽高**不可超过 2048**，否则无法显示。
- coverview 需基础库 **≥2.16.1**（插件已兼容，不支持时降级离屏 canvas 渲染进度）。
- `hideAfterCallmain`：业务 Awake 耗时高可能短暂黑屏，改 **false** 可盖住黑屏、等游戏第一帧渲染时隐藏。

### 4.3 Loader CDN 与首包加载配置

来源：微信适配文档 Design/UsingLoader.md（官方文档内容·镜像取得 BlackTom900131/minigame-unity-webgl-transform，gh api 核实 2026-11-14；原页待浏览器复核）。

**CDN 配置**（转换插件 `CDN` / `dataFileSubPrefix`，后者为首包资源相对 CDN 的存放目录，默认一级目录）：备用 CDN 切换用 C# `WX.SetDataCDN` 或 JS `GameGlobal.manager.setDataCDN` 修改 DATA_CDN。

**首包资源加载方式**（导出时确定，一般不改）：资源少时可作小游戏分包加载（`assetLoadType` / `loadDataPackageFromSubpackage`，资源放 `minigame/data-package` 分包）；**wasm 代码 + 首包资源 > 20M 时，资源包不可再用小游戏分包加载**。手动改 `loadDataPackageFromSubpackage=false` 须把 webgl 资源包传 CDN 并填 game.js `DATA_CDN`；改 true 须把资源包 copy 到 `minigame/data-package`。

**插件调试日志**：改 `minigame/unity-namespace.js` 的 `enableDebugLog=true` 看详细日志（预下载发起/命中、文件缓存）；真机开调试 `wx.setEnableDebug({enableDebug:true})`，**启动阶段点三次封面视频下方 Unity Logo 出现 vconsole**。

## 五、平台评测标准与目标值

### 抖音（官方规定，已核实）

来源：[抖音 Unity 小游戏性能评测标准](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/performance-optimization-both/unity/performance-optimization/unity-minigame-scoring-standards)，核对 2026-11-12。

指标口径：**FP80** = 80% 用户的首屏渲染时间；**TTI80** = 80% 用户的可交互时间。单位 ms。

| 设备档 | 平台 | FP80 优秀/建议/达标 | TTI80 优秀/建议/达标 |
|--------|------|---------------------|---------------------|
| 高档 | iOS | 2686 / 5212 / 9020 | 8045 / 13624 / 20825 |
| 中档 | iOS | 5021 / 8923 / 14010 | 12394 / 20046 / 28927 |
| 低档 | iOS | 10010 / 14919 / 19991 | 20930 / 33375 / 45131 |
| 高档 | Android | 4495 / 7286 / 10941 | 11758 / 17934 / 25153 |
| 中档 | Android | 8505 / 13135 / 18576 | 18903 / 27657 / 38099 |
| 低档 | Android | 7553 / 12885 / 18851 | 17794 / 28157 / 39989 |

**抖音性能优化总览建议**（来源：[性能优化总览](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/rd-to-SCgame/open-capacity/performance-optimization/sc_webgl_performance_optimization)，更新 2025-05-27，核对 2026-11-11）：
- 启动后建议下载 ≤ 10MB 资源即进首场景。
- 启动后建议进首场景时间 ≤ 5s。
- CDN 必须开压缩。
- 单个 AB 推荐 ≤ 2MB。
- 资源请求并发 ≤ 20（经验值）。
- 首场景 Awake/Start/首帧 Update 不放重逻辑。

### 微信（硬约束 + 官方启动指南已核实）

- 首包（主包）≤ 4MB（[分包加载文档](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage.html)，核对 2026-11-11）。
- **官方启动指南**（Design/StartupOptimization.md + FirstSceneOptimization.md，经镜像 BlackTom900131/minigame-unity-webgl-transform 取得，核对 2026-11-13；原页待浏览器复核）：
  - 首屏启动建议 **5~10s 甚至更短**；普通小游戏普遍 7~10s，未优化 Unity WebGL 是其 2-3 倍。
  - 首包网络传输量控制 **3~5MB**（务必压缩：转换面板「压缩首资源包」或 CDN 对 .txt 开 gzip/br）；玩家平均下载 ~2MB/s，存在 <300KB/s 低网速用户。
  - 中文字体用 **2~3MB 以内精简字体**（打包首包或 Bundle）。
  - 原始 code 包 **≤30MB**，勾 Strip Engine Code + Managed Stripping High；代码分包工具减到原始 1/3；Unity 2021+ 可设 IL2CPP SIZE 减小函数量。
  - **PlayerLoadFirstScene 耗时控制在 CallMain 的 ~20%**（Unity Benchmark 实测判据，Unity 2018.4.24f1 Development 模式）；首帧 Start/Awake 少逻辑、初始场景仅 Splash、后续加载分帧勿阻塞。
  - **预下载**（UsingPreload.md，镜像核实 round 27）：引擎初始化 + 首场景准备是 CPU 密集但网络空闲期（平均 3~6s），在此预下载资源缓存本地（完成后内存持有 60s 释放）。配置三式：导出列表（MiniGameConfig.asset `preloadFiles`）/ 手动 game.js `preloadDataList` / **运行时动态（推荐，抗热更）**——插件启动前 `GameGlobal.manager.setPreloadList` 或引擎初始化后 C# `WX.SetPreloadList(string[])`。并发：初始化前默认 10、初始化后默认 1（最大 10）；`WX.PreloadConcurrent` 改初始化后、`GameGlobal.manager.setConcurrent` 改初始化期间（初始化后会重置为 1）。
- **首场景 CPU Profile 法**（安卓，FirstSceneOptimization.md）：菜单→开发调试→Start/Stop CPU Profile→导出→Chrome JavaScript Profile 导入；改造 game.js（`loadingPageConfig.visible=false` + `startGame` 放入 `wx.onTouchStart`）以录制完整启动 Profile，重点看 PlayerLoadFirstScene 占比。
- 启动场景分析工具/启动留存上报仍待浏览器（perf-action-start2.html）；预下载策略与 Unity API 已核实（§五，UsingPreload.md 镜像），原生 `wx.preDownloadSubpackage` 参数细节待浏览器（predownload 页）。

**微信性能评测标准**（Design/PerfMeasure.md，镜像核实 round 38；标准更新 2024-08-13，基于现网玩家上报 + 云测试）：
- **体积标准**：首资源包（gzip 后）**<5MB**、WASM 代码（br 后）**<5MB**、核心玩法资源 **<30MB**。（评测下载量口径，与主包≤4MB 硬限不同）
- **启动指标定义**（微信口径，对应抖音 FP/TTI）：CALLMAIN = 引擎 + 首场景 Loading 初始化（timelog「CALLMAIN耗时」）；**游戏初始化完成** = 引擎 + 首场景完成、出现首个业务场景（timelog「游戏启动耗时」，≈FP）；**游戏可交互完成** = 核心场景完成（休闲 = 核心玩法，RPG = 创角；启动留存上报统计，≈TTI）。
- **运行指标**：内存峰值、FPS 均值（核心玩法 5 分钟均值，限帧逻辑故仅供参考）、卡顿率（5 分钟均值）、内存异常退出率/运行时长（iOS）。
- **游戏类型分档**：重度（MMO/SLG，多场景/多人）、中度（模拟经营/卡牌，养成 + 内购）、轻度（棋牌，简单操作无养成无内购）。
- **评测工具**：现网 = 性能监控系统 + 小游戏数据助手（数据-性能分析）/ MP 研发工具箱；开发 = 小游戏云测试（网络模拟 1MB/s）+ 性能诊断工具（开发版/体验版网络/接口/性能/启动耗时）。
- 具体分档阈值表在原文图片中（iOS/Android 启动/运行性能图），文本无法提取，待浏览器复核。

## 六、模板 Boot 实现对照（项目实测）

路径：`projects/MiniGameTemplate/Assets/_Project/Scripts/Core/`

**BootLoader.cs**（Boot 场景唯一入口）：
```csharp
private void Start()
{
    LoadingManager.Instance.LoadScene("Game", "进入游戏");
}
```
- Boot 场景只做初始化，不放游戏内容。符合「首场景最小化」原则。

**LoadingManager.cs**（统一 Loading）：
- DontDestroyOnLoad 单例，代码构建 UI（不依赖 Prefab/资源加载）。
- `allowSceneActivation = false` 接管进度：0~90% 反映真实加载，90% 后放行激活到 100%。
- 支持三种模式：LoadScene（真实进度）、Run（循环条）、Show/SetProgress（手动驱动）。

**优化衔接点**：
- 当前 Boot → Game 是同步 LoadSceneAsync，Game 场景资源全在 Build Settings。若 Game 场景膨胀，应改为 AB 加载 + LoadingManager.Run 包装。
- BGM 走远程 CDN 不进首包（架构条目已约定）。
- 纹理 ASTC、音频 AAC 低码率（架构条目已约定）。

## 七、优化决策树

```
首屏慢？
├─ 首包体积 > 4MB（微信）或 IDE 报错（抖音）
│   → 第二节首包精简 + 第三节 WASM 精简
├─ 首包已小但 TTI 仍高
│   ├─ Shader 编译耗时 → 清变体、延迟加载、异步 Warmup（第四节 §4.1）
│   ├─ 首场景 Awake/Start 重 → 移重逻辑到 Loading 后
│   └─ 网络下载慢 → CDN 压缩、分包预下载
└─ 抖音评测不达标
    → 对照第五节阈值，用 wasm 分包工具（第三节）
```
