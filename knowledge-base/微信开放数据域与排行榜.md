# 微信开放数据域与排行榜

适用：团结引擎 / Unity 2022.3 WebGL 微信小游戏（开放数据域为微信特有；抖音关系链 API 不同待核对）。
触发：做好友排行榜/群排行榜、接开放数据域展示微信关系数据、sharedCanvas 渲染与坐标/事件问题。
核对日期：2026-11-14（微信适配文档 Design/OpenData.md，经镜像 BlackTom900131/minigame-unity-webgl-transform gh api 取得；原页待浏览器复核）。
前置：能力矩阵见 [平台能力开通与接入检查](./平台能力开通与接入检查.md)（排行榜/开放数据域行）；本条目讲完整接入。

## 结论速览

1. **关系链数据只能在开放数据域取**（安全隔离）：独立文件夹拉好友数据 + 绘制到 sharedCanvas；**通信单向**（主域→开放数据域），主域靠定期刷新纹理同步。
2. **推荐 ScreenCanvas 模式**（基础库 **3.6.6+**）：在屏渲染，不依赖游戏域循环刷新，减少离屏干扰；OffScreenCanvas 是旧版（hook Unity 渲染替换纹理）。
3. **占位 RawImage 须 rotation X=180**（Unity 纹理与 Web 绘制倒立差异）；`WX.ShowOpenData` 传屏幕物理坐标（左上角 0,0）供开放域处理点击/滚动。
4. **OffScreenCanvas 模式关闭必须调 `WX.HideOpenData`**，只隐藏 RawImage 会纹理错乱。

## 1. 开放数据域原理

- 开放数据域逻辑在独立文件夹，核心两件事：调关系链接口拉好友数据 + 绘制到 **sharedCanvas**（离屏 canvas，不理解自己如何上屏）。
- 主域（业务代码）通过 sharedCanvas 创建精灵添加到场景；**数据通信单向**（主域→开放数据域），主域无法感知开放域内部，更新只能定期刷新纹理。
- Unity 实现核心是 **hook 渲染**：占位纹理对应 WebGLObject → 绘制排行榜时替换为 sharedCanvas 创建的 WebGLObject → 关闭时停止 hook。
- **ScreenCanvas 模式（基础库 3.6.6+）**：sharedCanvas 变在屏模式，不依赖游戏域循环刷新渲染，减少离屏 Canvas 干扰：

```csharp
WX.GetOpenDataContext(new OpenDataContextOption {
    sharedCanvasMode = CanvasType.ScreenCanvas   // 推荐；OffScreenCanvas 为旧版
});
```

## 2. 接入步骤

1. **占位纹理**：展示处建 RawImage（Texture 选透明图，后续动态替换）；**rotation X=180**（Unity 纹理与 Web 倒立），再调到合适位置。
2. **初始化**（canvas 类型初始化后不可改，只初始化一次保存）：`WX.GetOpenDataContext(new OpenDataContextOption{ sharedCanvasMode = ... })`。
3. **传消息**：`openDataContext.PostMessage(JsonUtility.ToJson(msg))`；开放域 JS `wx.onMessage(data => ...)` 按 type 分发（如 showFriendsRank）。
4. **展示**：`WX.ShowOpenData(rawImage.texture, x, y, width, height)`（坐标见 §3）。内部触发开放域初始化 + 抛 WXRender 事件 + （OffScreenCanvas）hook 渲染替换纹理 / （ScreenCanvas）改宽高直接在屏渲染。
5. **关闭**：`WX.HideOpenData()`（OffScreenCanvas 模式必须，见 §5 Q2）。
6. **导出勾选「使用好友关系链」**：game.json 声明开放数据域 + 拷贝插件内置 open-data 示例到 minigame 目录（做好备份）。
7. **JS 开发排行榜**：开放数据域只能用 JS；可用 Canvas2D（事件/滚动麻烦）或完整 JS 引擎（Cocos 但增包体）；插件示例用微信自研[轻量渲染引擎 minigame-canvas-engine](https://wechat-miniprogram.github.io/minigame-canvas-engine/)（压缩几十 k，需 Flex/CSS 基础）。参考 Demo/Ranking（仓库已封待复核）。

## 3. ShowOpenData 坐标换算

`x/y/width/height` 是占位区域在**屏幕的物理坐标**（左上角 0,0），供开放域正确处理点击/滚动（开放域非 Unity 渲染，需明确知道纹理绘制位置）。

- Constant Pixel Size：width 直接传 `(int)rectTransform.rect.width`。
- Scale With Screen Size（按宽缩放）：需按 referenceResolution 换算，如 `width = (int)(Screen.width / referenceResolution.x * rectTransform.rect.width)`；y 用 `Screen.height - (int)position.y`。
- 目的：算出 RawImage 在屏幕的绝对位置与尺寸（例 iPhone Xs Max 414×896，排行榜居中 200×200 → x,y,w,h = 107,348,200,200）。

## 4. 群排行榜

1. `WX.UpdateShareMenu(new UpdateShareMenuOption{ withShareTicket = true, isPrivateMessage = true })`。
2. 分享带 query：`WX.ShareAppMessage(new ShareAppMessageOption{ title=..., query="minigame_action=show_group_list", imageUrl=... })`。
3. `WX.OnShow` 回调取 `res.shareTicket` + `res.query`，匹配 minigame_action 后 InitOpenDataContext + ShowOpenData + PostMessage（type=showGroupFriendsRank，带 shareTicket）。

## 5. 常见坑（QA）

| 现象 | 原因/解法 |
|------|-----------|
| 第一次 ShowOpenData 画面先黑一下 | WXRender 事件后开放域无同步渲染→sharedCanvas 纹理未就绪；监听 WXRender 后先同步绘「好友数据加载中…」文案 |
| 关闭排行榜后纹理错乱 | 没调 `WX.HideOpenData`（OffScreenCanvas 模式）；加日志排查 |
| 开放域滚动/点击事件不生效 | ShowOpenData 的 x/y/width/height 不对（屏幕物理坐标，x/y 不应负数） |
| ScreenCanvas 模式 ToTempFilePath 无开放域画面 | ScreenCanvas 浮在主画布之上非同画布；用 `WXSharedCanvas.ToTempFilePath` |
