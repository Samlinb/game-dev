# 小游戏分辨率适配与降级策略

适用：团结引擎 / Unity 2022.3 WebGL 构建，微信 + 抖音小游戏平台，uGUI。
触发：UI 在刘海屏被遮挡、不同比例屏幕布局错乱、低端机帧率不达标。
核对日期：2026-11-12（Unity Canvas Scaler / 多分辨率设计指南 / 团结 ScriptReference）；2026-11-13 round 24 经镜像核实微信 fixScreen（WX.GetWindowInfo safeArea，见 §3.4）。抖音 safeArea/设备分档 API 仍待核对。

## 结论（影响行动的部分）

1. **Canvas Scaler 选 Scale With Screen Size**（模板已用，参考分辨率 1080×1920）。竖屏休闲游戏 Match 设 0.5 或按高度匹配，避免宽屏设备 UI 放大。
2. **锚点决定布局存活**：角落元素锚对应角落，全屏背景 Stretch。不锚定的元素换比例就飞出屏幕。
3. **安全区域不能只靠 Screen.safeArea**：WebGL 下该值是否反映刘海需真机验证；微信/抖音宿主提供平台级 safeArea API（`wx.getWindowInfo`），应优先用平台数据。
4. **胶囊按钮避让是微信特有**：`wx.getMenuButtonBoundingClientRect` 返回胶囊位置，右上角 UI 必须避让。
5. **低端机降级三件套**：帧率上限（模板已设 30）→ 渲染分辨率缩放 → Shader/特效裁剪。设备分档用平台 API（微信 `wx.getDeviceBenchmarkInfo`，抖音评测标准分高/中/低档）。

## 一、Canvas Scaler 选型（官方规定）

来源：[Unity Canvas Scaler](https://docs.unity3d.com/2022.3/Documentation/Manual/script-CanvasScaler.html)，核对 2026-11-12。

### 三种模式对比

| 模式 | 行为 | 适用 | 小游戏推荐 |
|------|------|------|-----------|
| Constant Pixel Size | 元素保持固定像素大小 | 工具型 Overlay（不随屏幕缩放） | 仅 Loading 等特殊层 |
| **Scale With Screen Size** | 按参考分辨率等比缩放 | 多分辨率适配 | **首选** |
| Constant Physical Size | 保持物理尺寸（mm/pt） | 需要真实物理大小的场景 | 不推荐（依赖设备 DPI 准确性） |

### Scale With Screen Size 配置

| 参数 | 推荐值（竖屏休闲） | 说明 |
|------|-------------------|------|
| Reference Resolution | 1080 × 1920 | 模板 LoadingManager 已用此值 |
| Screen Match Mode | Match Width Or Height | 允许混合 |
| Match | 0.5（或 1 = 按高度） | 0=按宽, 1=按高, 0.5=折中 |

**Match 的作用**（来源：[多分辨率设计指南](https://docs.unity3d.com/2022.3/Documentation/Manual/HOWTO-UIMultiResolution.html)，核对 2026-11-12）：
- 默认 Match=0（按宽）：横屏或宽屏设备宽度大于参考 → UI 整体放大 → 可能溢出。
- Match=0.5：宽高因子互相抵消，比例变化时 UI 大小稳定。
- **竖屏游戏建议 Match=1（按高度）**：高度是竖屏的主轴，宽度变化时允许左右留白或裁切。

### Expand vs Shrink

| 模式 | 行为 | 风险 |
|------|------|------|
| Expand | Canvas 只扩不缩，保证不小于参考 | 宽屏设备可见区域变大，边缘元素可能离中心更远 |
| Shrink | Canvas 只缩不扩，保证不大于参考 | 小屏设备可能裁切内容 |

**推荐**：Match Width Or Height + Match=0.5~1，不用 Expand/Shrink（除非有明确的全屏覆盖需求）。

## 二、锚点策略（官方规定）

来源：[多分辨率设计指南](https://docs.unity3d.com/2022.3/Documentation/Manual/HOWTO-UIMultiResolution.html)，核对 2026-11-12。

| 元素类型 | 锚点设置 | 模板工具 |
|----------|----------|----------|
| 角落按钮（设置/暂停） | 锚对应角落（如右上 anchor=(1,1)） | `UGUIUtil.SetAnchor(rt, new Vector2(1,1), pos, size)` |
| 全屏背景/遮罩 | Stretch（anchorMin=0, anchorMax=1） | `UGUIUtil.Stretch(rt)` |
| 居中弹窗 | 锚中心 (0.5, 0.5) | `UGUIUtil.SetAnchor(rt, Vector2.one*0.5f, pos, size)` |
| 底部操作栏 | 锚底部拉伸（anchorMin=(0,0), anchorMax=(1,0)） | 手动设或扩展 UGUIUtil |

**工作流**：在设计分辨率下摆好位置 → 设锚点 → 加 Canvas Scaler → 逐一切换目标分辨率/比例验证。

**模板现状**：`UGUIUtil.cs` 提供 SetAnchor/Stretch 工具方法，LoadingManager 代码建 UI 已正确使用。正式面板 Prefab 需美术在编辑器中按此规则设锚点。

## 三、安全区域与刘海屏

### 3.1 Screen.safeArea（引擎层）

来源：[团结 ScriptReference Screen.safeArea](https://docs.unity.cn/cn/tuanjiemanual/ScriptReference/Screen-safeArea.html)，核对 2026-11-12。

- 返回 `Rect`（像素），表示屏幕中不被遮挡的区域。
- 最大值 = `Rect(0, 0, Screen.width, Screen.height)`。
- **WebGL 行为待验证**：官方文档无 WebGL 平台说明。浏览器不向 Web 内容暴露刘海信息，`Screen.safeArea` 在 WebGL 下可能恒返回全屏。

**验证方法**（需真机）：
```csharp
Debug.Log($"safeArea={Screen.safeArea}, screen={Screen.width}x{Screen.height}");
// 在刘海屏真机（iPhone 14+）微信/抖音中运行，对比 safeArea 是否小于全屏
```

### 3.2 平台 API（宿主层，推荐优先使用）

| 平台 | API | 返回 | 来源状态 |
|------|-----|------|----------|
| 微信 | `wx.getWindowInfo()`（C# 封装 `WX.GetWindowInfo()`） | 含 `safeArea`（left/right/top/bottom/width/height）+ windowWidth/windowHeight | **已核实（round 24 镜像 fixScreen.md）**：safeArea 数值须乘 pixelRatio 才为 Unity 大小；屏幕左上角为 (0,0) |
| 微信 | `wx.getMenuButtonBoundingClientRect()` | 胶囊按钮位置（右上角） | 同上 |
| 抖音 | `tt.getSystemInfoSync()` | 含 safeArea 字段（待确认） | 待核对 |

**微信胶囊避让**：右上角 UI（设置按钮等）必须避开胶囊区域。胶囊位置通过 `getMenuButtonBoundingClientRect` 获取，不能用固定偏移（不同机型胶囊位置不同）。

### 3.4 微信官方 fixScreen 方案（镜像取得已核实）

来源：微信官方适配文档 `Design/fixScreen.md`，经镜像 BlackTom900131/minigame-unity-webgl-transform 取得（gh api，2026-11-13）；原页待浏览器复核。官方文档内容。

**安全区域适配**：小游戏屏幕适配与常见 Unity 手机适配无异，区别在屏幕信息获取——安全区域须调 `WX.GetWindowInfo()` 取 `safeArea`。**关键：safeArea 数值须乘 pixelRatio 才为 Unity 中的大小；手机屏幕左上角为 (0,0)**（y 轴向下，与 Unity 相反）。

官方刘海屏示例（竖屏按高度适配）：
```csharp
var info = WX.GetWindowInfo();
float py = (float)info.safeArea.top / (float)info.windowHeight;
// Rootrect 初始 Anchor 与父节点同大（屏幕大小）；移到刘海屏下面
Rootrect.anchorMin = new Vector2((float)info.safeArea.left / (float)info.windowWidth, -(float)info.safeArea.top / (float)info.windowHeight);
// 重算缩放，让高度占满刘海屏以下区域
cs.referenceResolution = new Vector2(cs.referenceResolution.x, cs.referenceResolution.y * (1.0f + py));
```

**高分辨屏模糊**：Unity 2019.3 之前对高分辨屏适配不佳会模糊，建议用 Unity 2019.3+ 构建；不能升级则引入 SDK，`WX.InitSDK((int code)=>{ /* 主逻辑 */ })` 初始化后 SDK 自动做页面兼容适配避免模糊。

### 4.2 降级手段（按 ROI 排序）

| 手段 | 实现 | 效果 | 模板现状 |
|------|------|------|----------|
| **帧率上限** | `Application.targetFrameRate = 30` | 直接降 CPU/GPU 负载 | ✅ GameConfig.targetFrameRate=30，GameManager 已应用 |
| **渲染分辨率缩放** | `Screen.SetResolution(w*scale, h*scale, false)` | 降 GPU 填充率 | ⚠️ WebGL 行为待验证（见下） |
| **Shader/特效裁剪** | QualitySettings 切换、禁用粒子/后处理 | 降 GPU 复杂度 | 见 [DrawCall 与渲染批处理优化](./DrawCall与渲染批处理优化.md) |
| **纹理降级** | 低档机用更小 maxsize / 更激进压缩 | 降内存+带宽 | 见 [Unity 真机 Profiling](./Unity真机Profiling与内存分析.md) |
| **同屏数量限制** | 减少敌人/特效/Spine 同屏数 | 降 CPU+DrawCall | 按游戏设计定 |

### 4.3 Screen.SetResolution 在 WebGL 的行为

来源：[团结 ScriptReference Screen.SetResolution](https://docs.unity.cn/cn/tuanjiemanual/ScriptReference/Screen.SetResolution.html)，核对 2026-11-12。

- 官方文档无 WebGL 平台说明。
- 已知：分辨率切换在当前帧结束后生效；无匹配分辨率时取最近值。
- **待验证**：WebGL 下调用是否改变 canvas drawing buffer 尺寸（还是被宿主忽略）。

**验证方法**（需真机/开发者工具）：
```csharp
Screen.SetResolution(Screen.width / 2, Screen.height / 2, false);
// 观察：画面是否变模糊（渲染分辨率降低）、帧率是否提升
// 对比：微信开发者工具 Performance 面板的 GPU 耗时
```

**替代方案**（若 SetResolution 无效）：通过宿主 JS 修改 canvas 的 width/height 属性（需 SDK 桥接），或接受固定分辨率 + 其他降级手段。

### 4.4 降级决策树（示例）

```
启动时获取设备分档
├─ 高档：targetFrameRate=60，全特效，原始分辨率
├─ 中档：targetFrameRate=30，关闭后处理，原始分辨率
└─ 低档：targetFrameRate=30，关闭后处理+粒子减半，
         分辨率×0.75（若 SetResolution 有效），纹理 maxsize 减半
```
