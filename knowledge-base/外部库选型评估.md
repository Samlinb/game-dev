# 外部库选型评估

适用于已找到候选库或代码、决定接入之前的核对。目标是把"能不能用"变成逐项可核对、可给出理由的结论，而不是按星数拍板。评估不通过时回到 [写新功能前先找现成实现](./写新功能前先找现成实现.md) 的四选一决策。

## 评估清单

每项写明"看什么"和"不通过时的分支"：

| 维度 | 看什么 | 不通过的分支 |
| --- | --- | --- |
| 活跃度 | 最近 commit / release 时间 | 超过一年未更新 → fork 或自写 |
| 维护者 | 贡献者数量（bus factor）、是否有基金会或公司背书 | 单人维护 → 供应链门槛加严一档 |
| issue | 响应速度、open/closed 比例 | 长期无人应 → 质量不足，自写或另找 |
| 质量证据 | 测试、CI、文档、示例 | 无测试且无文档 → 接入成本转嫁给自己 |
| 许可证 | LICENSE 文件本体 | 冲突 → 放弃或替换，见下表 |
| 依赖树 | 它拉进来的其他包 | 依赖深 → 评估范围扩大到整棵树 |
| 平台兼容 | 引擎版本、IL2CPP / WebGL 支持、包体影响 | 不兼容 → 锁旧版或自写；小游戏平台对包体敏感 |
| 使用面 | 生产使用者数量、社区讨论 | 无人使用 → 其余各项门槛提高 |

## 许可证对比（核对 2026-11-11）

整理自 [choosealicense.com/licenses](https://choosealicense.com/licenses/)（GitHub 维护）与 [GitHub licensing 文档](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)：

| 类别 | 许可证 | 关键条款 | 闭源商业项目 |
| --- | --- | --- | --- |
| 宽松 | MIT | 保留版权与许可声明即可 | 可用 |
| 宽松 | Apache-2.0 | 保留声明并声明修改；显式专利授权，禁用商标 | 可用，专利保护更明确 |
| 弱 copyleft | MPL-2.0 | 仅许可文件本身须开源，新增文件可另选许可 | 按文件隔离使用 |
| 弱 copyleft | LGPL-3.0 | 库自身开源；通过接口调用的大作品可另选许可且不必开源 | 可行，链接方式逐案核对 |
| 强 copyleft | GPL-3.0 | 衍生作品（含引入它的更大作品）必须同许可开源并公开源码 | 闭源不可用 |
| 强 copyleft | AGPL-3.0 | 同 GPL，且修改版作为网络服务运行也须开源 | 闭源服务端不可用 |

补充：以上许可证都允许商业使用，差别在条件（公开源码、同许可等）；强 copyleft 的"传染"来自 same license 条款。编辑期工具（构建脚本、编辑器插件）与运行时代码的许可要求不同，逐案核对条款，拿不准时不接入。

## 供应链风险与缓解

[写新功能前先找现成实现](./写新功能前先找现成实现.md) 记录了三个已核实的事故，对应三种风险模式与接入时的识别信号：

| 事故 | 模式 | 识别信号 |
| --- | --- | --- |
| event-stream（2018） | 停维包被转手给陌生账号 | 查维护者变更历史；近期转手要谨慎 |
| xz（2024） | 渗透获得维护权后注入后门 | 单人维护 + 无签名发布 + 高价值目标是共同模式 |
| left-pad（2016） | 依赖链单点 | 依赖树深度；传递依赖也值得锁版本 |

缓解措施按成本从低到高：

1. 锁定版本与哈希，不跟踪 `latest` 或主分支。
2. 接入前读将要执行的代码和它的依赖树；升级时 diff 审查。
3. 优先多维护者、带签名发布、有基金会或公司背书的库。
4. 涉及支付、账号、资产的高价值目标，门槛加严一档。

## Unity 接入方式（核对 2026-11-11）

来源 [upm-concepts](https://docs.unity3d.com/2022.3/Documentation/Manual/upm-concepts.html)。Package Manager 的六种包来源：

| 来源 | 可变性 | 适用 |
| --- | --- | --- |
| Registry | 不可变，全局缓存 | 优先选：有语义化版本、依赖解析、版本冲突处理 |
| Built-in | 不可变，随引擎捆绑 | 引擎功能模块开关 |
| Git | —— | 上游不在 Registry 时；锁定 commit |
| Local / Embedded / Tarball | Local、Embedded 可变；Tarball 不可变 | fork 自维护、本地改造 |

fork 自维护时用 Local / Embedded 源，在仓库 README 记录 fork 原因、上游地址和本地差异，方便后续合并上游修复。
