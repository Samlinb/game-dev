## 七、核心避坑清单（提炼版）

### 通用原则
1. **先 Profile 再优化，且必须真机 Profiling** —— Editor 数据不代表真机；用毫秒（帧时间）衡量，不用 FPS；追求稳定帧率而非峰值
2. **美术标准在项目前期确立** —— 后期换美术规格的优化成本极高
3. **引擎/技术选型定了就别换** —— 频繁换技术栈是独立开发者最大的时间黑洞

### CPU / 代码
- Update/FixedUpdate/LateUpdate 里不写昂贵代码；音频开销常被忽视
- 缓存 `GetComponent()` 结果；用 `CompareTag()` 不用字符串比较 tag；不滥调 `Find()`
- 复用集合与对象池，避免每帧分配 → GC 尖峰；警惕 LINQ、闭包、装箱产生的隐藏分配
- 物理慎用 Mesh Collider，用基本几何碰撞体；配好 Layer Collision Matrix 减少无效检测

### GPU / 渲染
- DrawCall 批处理（合图集、SRP Batcher）、Occlusion Culling、LOD
- 减 OverDraw（半透明 UI 叠加是重灾区）、提高 Early-Z 命中率、Shader 精简
- 纹理按目标平台压缩，降低 GPU 带宽

### 内存
- 纹理压缩格式按平台选；资源避免重复加载；AB/动态资源及时卸载
- 动态加载的资源在场景切换时不会自动释放（Cocos 尤其注意），要显式管理

### 小游戏特有
- 微信首包限 4MB → 代码分包 + 远程资源；iOS 基础库常驻约 65M 内存必须预留
- 启动耗时是"即开即用"场景的第一指标：首屏加载、分包预下载
- 压缩纹理替代 PNG/JPG 解码；用官方数据助手监控线上内存趋势

### Spine
- 骨架复杂度能减则减；多骨架 round-robin 分帧更新不可见/次要动画
- 减 atlas 数量、共享材质降 DrawCall；懒加载按需实例化
- 简单 UI 动画别用 Spine（CPU 换美术资源的账要算清）

### 项目管理
- 别 overscoping：起步太大、功能堆砌是独立项目头号死因
- 尽早 Playtest、营销从开发第一天就开始、别把音乐音效留到最后
