# 真机白屏与资源加载失败排查

> 适用范围：Unity WebGL / 团结引擎导出的微信与抖音小游戏。"白屏/黑屏"指首屏无任何可见画面（包括 Loading 条）或运行中突然消失，通常伴随 vConsole 中 JS/WASM/Shader 报错。
> 不适用于：微信原生小游戏（非 Unity 导出）、Cocos 小游戏（有独立条目）、开发工具模拟器正常但真机才出问题的场景（本条目覆盖）。

---

## 0. 先拿到调试窗口

白屏排查第一步**一定是先让真机吐日志**。开发工具模拟器报错不够用，真机上微信/抖音的环境差异才是白屏真正的来源。

### 微信

1. **永久代码开关**：在 `game.js` 最前面加：

```js
wx.setEnableDebug({ enableDebug: true })
```

   重新编译并走体验版二维码才能生效。

2. **真机手动开关**：右上角「...」→ **打开调试** → 完全退出小游戏（划掉进程）→ 重进 → 右上角「...」→ **vConsole**。

3. **Unity 适配的额外彩蛋**：如果启动封面不显示 vConsole，**点 3 次下方的 Unity Logo** 强制打开。

**来源**：微信 Unity 适配技术常见问题 QA §4，核对日期 2026-11-12。https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/DevelopmentQAList.html

**注意**：微信开发者工具的「真机调试」功能**不要用**——Unity 适配方案不支持，它只能用于原生小游戏。真机预览请走开发者工具的「预览 → 二维码 / 自动预览」。

### 抖音

1. 加入测试设备列表（开发者后台已完成）后，抖音 App「我」→ 右上角更多 → **开发者模式**（Android 需要重启抖音）。
2. 进入要调试的小游戏子菜单 → 打开「调试控制台」。
3. 进游戏后右上角「...」→ **打开调试** → **vConsole**。

版本要求：抖音 >= 27.1.0。

**来源**：抖音开放平台 vConsole 文档（更新时间 2025-04-30），核对日期 2026-11-12。https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/runtime/debug/vconsole

### Unity 侧的 Debug Build

在 Unity 打包面板勾选 **Development Build**：
- 关闭代码压缩，`framework.js` / `loader.js` 里保留可读的函数名
- 自动连上 Profiler（如果 Player Settings 里勾了 Connect Profiler）
- **Full Exception Support**（Player Settings → Web → Other Settings → Configuration）开启托管堆栈——但会显著增大 WASM 体积、降低加载速度，**只在调试时开**，上线前必须关掉

浏览器版 Unity WebGL（不走小游戏）打开 F12 直接看 Console 即可。小游戏里 vConsole 的 Console 面板和浏览器 F12 一样能看到 `Debug.LogError` 的输出。

**来源**：Unity Manual Debug Web builds in development，核对日期 2026-11-12。https://docs.unity3d.com/Manual/web-debugging-development.html

## 1. 定位顺序：从现象到根因

下面这个顺序是实战中最高效的排查路径，从上到下每一步的验证成本都低于下一步。vConsole 打开后，**先按这个顺序扫一遍，不要跳步**。

### Step 1：先看 vConsole Console 面板第一条 Error

白屏场景 90% 的首条 Error 已经直接指向根因。典型报错模式见第 2 节原因清单。

如果 Console 面板全是红色滚动刷不过来，说明上游某个初始化异常导致后续连锁失败。**找时间线最早的一条 Error**——它才是第一现场。

### Step 2：Network 面板 → 找红色 404 / CORS 失败

**核心检查项**：
- `framework.js` / `loader.js` / `.wasm` / `.data` / `.symbols.json` 是否全 200
- 首资源包里的 `game.json`、`game.js`、`wasmcode` 路径是否正确
- CDN 的 `application/wasm` Content-Type 和 `Content-Encoding` 是否对齐压缩格式（gzip→`.gz`→`Content-Encoding: gzip`；Brotli→`.br`→`Content-Encoding: br`）

**白屏杀手 Top 1**：CDN 404 某个 wasm 分片 → 整个 Unity 引擎启动失败 → 全白屏。微信 Unity 适配的 wasm 体积通常 30MB（压缩后 ~6MB），启动阶段必须下载完才能编译。

### Step 3：是分包的问题吗？

微信 Unity 适配的代码分包工具在引擎+业务首场景初始化时会收集函数引用。如果某个反射/动态调用的函数没被收集到，**开发版本会弹"首次拉取代码分包"提示**，同时 vConsole 报 `Missing method` 或类似错误。

复测：更新到最新分包工具 → 重新导出一轮 → 真机重扫。

### Step 4：基础库兼容

vConsole 里如果看到 `API xxx is not a function` 或 `Unsupported API` 类报错，基本锁定：
- 小游戏基础库版本低于某 API 的最低要求（微信/抖音开放平台后台查基础库最低版本设置）
- Unity WebGL 转换工具版本过旧，没有适配新的基础库变化

复测：在开发者工具里切换到目标基础库版本 → 模拟运行 → 真机也切到同一基础库体验版。

## 2. 常见原因清单

### 2.1 压缩 / 服务器头配置错 → 首包加载失败白屏

**现象**：vConsole Console 报 `Failed to decompress file` / `Content-Encoding mismatch` / `Decompressing this format isn't supported`。Network 面板里某个 `.unityweb` / `.gz` / `.br` 文件 200 了但实际解压失败。

**根因**：
- Unity Player Settings 里压缩格式选了 gzip 或 Brotli，但服务器 CDN 返回的 `Content-Encoding` 不对或根本没设
- Brotli 只在 HTTPS 浏览器原生支持（HTTP 下只有 gzip），如果 Decompression Fallback 也没勾，Brotli 文件会完全无法加载

**微信 Unity 适配特殊规则**：Unity Player Settings 的压缩选项**保持不压缩**——微信转换工具会对代码包自动做 br 压缩。资源包（CDN 上的 AssetBundle / 远程资源）才用 gzip/br，按服务器能力选。

**修复**：
1. 临时在 Player Settings → Web → Publishing Settings 里勾 **Decompression Fallback**（Unity 自带 JS 解压，绕开服务器头问题，但 loader 体积变大、加载变慢）
2. 或者服务器配置对齐：`.wasm.gz` → `Content-Type: application/wasm` + `Content-Encoding: gzip`；`.wasm.br` → `Content-Type: application/wasm` + `Content-Encoding: br`

**复测**：CDN 改头后等缓存刷新 → Network 面板看 Content-Encoding / Content-Type → 真机重扫。

**来源**：Unity Manual Deploy a Web application + 微信 Unity 适配 QA §5，核对日期 2026-11-12。

### 2.2 CDN 404 某个 wasm / data 分片 → 全白屏

**现象**：Network 面板里 `xx.wasm` 或 `xx.data` 显示红色 404 / 403。Console 报 `XMLHttpRequest failed` 或 `Fetch error`。

**根因**：
- 代码包里的路径前缀和 CDN 实际存放路径不一致（导出面板"游戏资源 CDN"填的 URL 末尾少 `/` 或多了子目录）
- CDN 目录结构和 Unity 导出时不一致（比如 wasmcode/ 目录被漏传）
- CORS 未配置：CDN 没有返回 `Access-Control-Allow-Origin: *`（小游戏不走浏览器同源策略，但 CDN 默认配置经常漏）

**微信 Unity 适配特殊**：首资源包（游戏代码）放 CDN 或 HTTP 服务器都行，但必须在导出面板的「游戏资源 CDN」里正确填写——填错了开发者工具也能跑（因为本地有），真机才白屏。

**复测**：导出面板改 CDN URL → 重新导出 → 真机重扫。

**来源**：微信 Unity 适配 QA §7-§8 + Unity Manual Build folder structure，核对日期 2026-11-12。

### 2.3 Shader 编译错误 → 黑屏（不是白屏但经常一起被问）

**现象**：开发者工具能跑但真机黑屏或只有 Loading 条。vConsole Console 报大量 `Shader compilation error`，常见关键词：`WebGL1` / `unsupported` / `pass index 1` / `Hidden/Universal/CoreBlit`。

**根因**：
- 默认导出是 WebGL 1.0（OpenGLES 2.0），Unity 6 以后默认 Auto Graphics API = WebGL 2.0，如果项目里用了 WebGL 2.0 专属特性（GLES3.0 shader、Compute Shader、Transform Feedback），真机 WebGL 1.0 环境下全部 shader 编译失败 → 黑屏
- URP 隐藏 shader：`Hidden/Universal Render Pipeline/LutBuilderLdr`（颜色分级）、`Hidden/Universal/CoreBlit`（URP Blitter pass 1）在微信真机 WebGL 1.0 下不支持
- Shader 里用了 `half` 精度但 WebGL 1.0 不支持——`Shader Precision Model` Player Settings 默认是 `Half`，切到 `Float` 能解决（但性能/内存成本要自己量）

**修复**：
1. 先在 Unity Player Settings → Web → Other Settings → Rendering 里勾 **WebGL2**（微信 Unity 适配有对应勾选入口「WebGL2 实验能力」）→ 真机重测
2. 确认项目是否真的需要 URP。如果用的是内置管线/BRP，这些问题不会出现
3. URP 必须用 WebGL 1.0 时：禁用颜色分级（URP Asset → Color Adjustments → 关掉）、把 `Library/PackageCache/unity.render-pipelines.universal@xxx/Shaders/Utils/CoreBlit.shader` 只保留第一个 Pass
4. Shader Precision Model 临时切 Float 验证后再考虑降精度

**复测**：真机重扫看 shader 编译错误是否消失。

**来源**：微信 Unity 适配 QA §8 + §11（URP CoreBlit）+ Unity Manual Web graphics APIs + WebPlayerSettingsWebGL Rendering 节，核对日期 2026-11-12。

### 2.4 Scripting Backend 非 IL2CPP → 团结引擎 Loading 卡死

**现象**：只在团结引擎（Tuanjie Engine）导出的真机上出现。Loading 界面卡住不动，Console 报：

```
MONO_WASM: Failed to load config file ./blazor.boot.json
```

**根因**：Scripting Backend 选了 Mono（默认），但团结引擎的 Unity WebGL 转小游戏链路只支持 IL2CPP。

**修复**：Unity Player Settings → Web → Other Settings → Configuration → **Scripting Backend 强制切 IL2CPP**。

**复测**：重打包 → 真机重扫。

**来源**：微信 Unity 适配 QA 平台适配 §10，核对日期 2026-11-12。

### 2.5 内存不足 → wasm 编译失败白屏

**现象**：Loading 条跑到某个百分比（比如 50-80%）后卡住或跳转。vConsole Console 报 `Out of Memory` / `WebAssembly.Memory allocation failed` / `Maximum call stack size exceeded`。

**根因**：
- wasm 体积过大导致浏览器在编译阶段内存爆掉（Unity 手动分包 + wasm 代码分包工具能显著减小启动时需一次下载/编译的 wasm 体积，首屏建议 wasm 压缩后 < 4MB）
- Unity Player Settings → Web → Configuration 里的 WebGL Memory Size 设得过大（默认 256MB，iOS 小游戏基础库常驻 65M 必须预留，真机总内存预算 iOS ~200MB、Android 差异较大）
- 代码裁剪级别设太低（Managed Stripping Level 默认 Low 导致托管代码冗余，wasm 体积膨胀）

**修复**：
1. Player Settings → Web → Configuration → **WebGL Memory Size** 降到 256MB 或更低（先验证 128MB 能不能跑起来，再往上调）
2. **Managed Stripping Level 设 High**，配合 link.xml 显式保留反射/动态调用的类型
3. 用微信代码分包工具把 wasm 按函数收集器分成多片

**复测**：真机看 vConsole 的 `Total Memory / Used Heap` 监控值（微信 Profiling 插件 ProfileStats 面板）。

**来源**：Unity Manual Memory in Unity Web + 微信 Unity 适配 QA §11（代码裁剪），核对日期 2026-11-12。

### 2.6 首资源包 CDN 配置漏填 / game.json 找不到

**现象**：开发者工具提示 `资源下载失败` 或微信 Unity 适配导出的真机 `game.json` 报 404。

**根因**：导出面板里「游戏资源 CDN」没填或填错。开发者工具能正常跑（因为本地有导出的 minigame 文件夹），只有真机才走 CDN。

**修复**：把导出的首资源包上传到 CDN，然后在 Unity 转换工具的导出面板里填入 CDN 根路径。路径末尾的 `/` 不能少。

**复测**：开发者工具里打开导出目录的 `/minigame` 子文件夹（不是根目录）→ 真机预览。

**来源**：微信 Unity 适配 QA §2 + §7，核对日期 2026-11-12。

## 3. Unity WebGL 小游戏特有坑

下面这些不是"白屏"而是 Unity WebGL 环境行为差异，会在特定场景下放大成白屏或数据全丢。

### 3.1 PlayerPrefs 别直接用

Unity WebGL 平台 PlayerPrefs 底层走浏览器 IndexedDB，单域名下总存储上限 **1MB**。小游戏环境下：
- Unity PlayerPrefs 在部分旧基础库版本上不工作
- 玩家删除本地小游戏后 Unity PlayerPrefs 会被清掉
- 1MB 限制非常容易被 JSON 存档涨爆

**替代方案**：
| 方案 | 存储上限 | 特点 |
|------|----------|------|
| WX C# SDK PlayerPref | 小游戏 Storage 10MB | 同步接口（阻塞），不建议高频调用 |
| WX C# SDK 文件 API | 文件系统 200MB | 异步，与游戏资源缓存共用区域 |
| 云开发 / 自建服务器 | 无上限 | 推荐，玩家删除小游戏不丢失存档 |

**抖音**：同样走 Storage API，大小限制待核对。

**来源**：微信 Unity 适配 QA 平台适配 §8 + Unity Scripting API PlayerPrefs（WebGL IndexedDB + 1MB 限制），核对日期 2026-11-12。

### 3.2 System.Net / System.File 命名空间不能用

Unity WebGL 平台禁止加载非源码编译的 DLL 插件。`System.Net`、lua 外部模块、依赖平台的第三方插件在 Unity WebGL 构建时会直接报 `Unable to load DLL`。

**修复**：网络走 UnityWebRequest + 适配层，文件存储见 3.1。

**来源**：微信 Unity 适配 QA Unity WebGL §1-§2，核对日期 2026-11-12。

### 3.3 中文字体不显示

Unity WebGL 环境下 Editor 能看到的字体在真机上全没了——因为真机没有 Unity Editor 里引用的系统字体。解决方案是把字体文件（TTF/OTF）打包进首资源包或 AssetBundle，字体体积控制在 **2~3MB 以内**。

**来源**：微信 Unity 适配 QA Unity WebGL §5，核对日期 2026-11-12。

### 3.4 LoadingManager 错误处理可以接得更紧

模板工程 `projects/MiniGameTemplate/Assets/_Project/Scripts/Core/LoadingManager.cs` 目前只在场景 `LoadSceneAsync` 返回 null 时 LogError（场景不在 Build Settings）。真机白屏排查时可以扩展这个类：
- 在协程 try/catch 里把任何异常信息 `LogError` 并展示在 Loading 面板上
- 给各资源加载 API（Addressables.LoadAssetAsync / AssetBundle.LoadAssetAsync）统一接失败回调，把错误信息写到屏幕上的 Tip UI 里
- vConsole 开着时直接 `wx.setLog`/`tt.setLog` 把关键状态也推送过去

### 3.5 Texture 2D 格式限制（微信特有）

Unity Player Settings → Web → Other Settings → Rendering 里的 **Texture Compression Format** 选项在小游戏环境下需要特别注意：
- 微信小游戏真机强制走 WebGL 渲染管线，ETC2/ASTC 格式的纹理在 Android 真机上可能因不支持显示成紫色块或全透明
- 建议打包时把 Unity Texture 的 Compression 设为 RGB24 / RGBA32（未压缩）先验证，再逐步切压缩格式

**来源**：Unity Manual Texture compression in Web + UWA 小游戏优化简谱，核对日期 2026-11-12（压缩格式兼容性待真机实测）。

## 4. 复测怎么算通过

白屏修复后的验收要走这个清单：
- [ ] vConsole Console 面板**没有新 Error**（Warning 可以先留着）
- [ ] Network 面板 200 率 100%，尤其是 `.wasm` / `.data` / `.framework.js`
- [ ] wasm 加载+编译时间在真机上 ≤ 首屏 TTI 指标（微信要求 ≤ 3s 左右）
- [ ] iOS 和 Android 都跑过同一版本（iOS WebGL 1.0 限制更严）
- [ ] Unity Player Settings 里的 Full Exception Support **已关闭**（上线版本必须关）
